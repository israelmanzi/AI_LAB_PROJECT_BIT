# 1.3 Searching: Linear and Binary Search

> **Status:** outline only · **Owner:** _TBD_ · **Reviewer:** _TBD_

## Learning outcomes
- Trace linear and binary search on a list.
- Explain why binary search requires a sorted list.
- Compare their worst-case steps (n vs log₂ n).

## Key ideas
- Linear search checks every item in turn: O(n).
- Binary search halves the remaining range each step: O(log n).
- 1,000,000 items take at most 20 binary-search steps.

## Terms to define
search, sorted, midpoint, O(log n)

## Worked example (planned)
Trace binary search for 23 in `[2, 5, 8, 12, 16, 23, 38, 56, 72, 91]`. Also test an odd-length list and a value that is not in the list.
